# Windows 桌面应用

## 为什么原来采用浏览器界面

原版是本地 Node.js 服务，扫描文件、启动 Java 服务器和下载工坊均在用户电脑运行，浏览器只负责界面，并非云服务。优点是开发与调试快、现有功能能共享同一套接口；缺点是依赖 Node 安装，浏览器和服务进程分离，窗口关闭不等于进程结束，打包和本机资源选择体验不直观。

## 当前重构

Electron 提供独立桌面窗口和内置 Node 运行环境。界面仍使用 HTML/CSS/JavaScript，这是桌面 UI 的实现方式，用户无需单独打开浏览器。现有管理服务运行在 utilityProcess 子进程，只监听随机的 127.0.0.1 端口；没有对局域网开放。窗口保持 sandbox 和 contextIsolation，禁用 nodeIntegration；preload 仅开放窗口控制、目录选择、数据目录和用户选择位置的日志导出。

Electron 能最大程度保留现有代码，但会增加安装包体积和内存占用。Tauri / WebView2 可以减小分发体积，但需要额外维护 Rust / .NET 层、系统 WebView 依赖及 Node 服务生命周期；此版本优先减少业务迁移风险。没有从参考 EXE 推断其技术栈，仅参考用户提供的截图布局。

## 开发与打包

- 安装依赖：npm ci
- 桌面开发：npm start
- 原浏览器模式：npm run start:web
- 运行检查：npm test
- 生成 Windows 解包目录：npm run pack:win
- 生成便携 EXE：npm run dist:win
- 产物目录：release。EXE 为未签名的 x64 便携版本；首次启动会解压运行时，不是一个无外部数据的静态程序。

## 数据与旧服务器包

开发模式沿用源码目录的 data 和 output。打包后使用 Windows 用户应用数据目录 PZ Server Studio/workspace，避免写入安装目录或 ASAR。旧存档和旧服务器包不会被复制或重置：到“项目与资源”的“已有服务器包”填写原服务器包目录并扫描即可继续使用。应用数据目录按钮可直接查看新的工作空间。游戏原有用户配置仍由既有扫描逻辑发现。

## 退出和后台任务

单实例锁避免重复打开桌面管理器。有服务器进程、下载或构建任务时，关闭窗口只允许返回或收起到托盘；托盘可以重新打开工作台。需要退出时，先保存并停止服务器并完成任务，再关闭应用。无活动任务也会询问是否已保存项目。运行实例不会因为普通关闭窗口被强制杀死。后台服务异常退出时会显示错误，不伪装为仍已连接。

## 界面

固定侧栏：首页、开服、模组、项目与资源、服务器配置、构建与测试、日志。首页数据来自现有扫描及运行状态，不使用示例数据。首次引导可跳过或通过问号重新打开。保留所有原配置编辑、前置依赖排序、下载与终端功能。支持深浅主题、Ctrl+S、原生目录选择。日志页只保留本次会话最近 200 条反馈与当前终端快照，不宣称是持久审计记录。分享导出日志前检查私人路径和连接信息。

## 本次验证

原有 69 项业务回归检查通过，新增 2 项桌面服务检查通过；使用打包后的 Electron 窗口验证 7 个页面、原生窗口操作、隔离 preload、深浅主题与首次引导，未出现页面 JavaScript 异常。使用本机 Edge 无头模式补充验证 1000px 宽度无横向溢出。可使用 `npm run verify:desktop` 重复桌面窗口检查（不会启动游戏服务器或修改存档）；测试截图保存在 release/preview。

首次下载 Electron 运行时可能需要网络代理；开发启动和打包脚本会复用现有系统代理。若官方大文件下载不畅，可以自行设置 ELECTRON_MIRROR 后重试，仍保留校验和验证。
