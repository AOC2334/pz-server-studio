# 项目计划与交付边界

## 产品目标

为 Windows 上的 Project Zomboid 玩家提供本地服务器配置工作台，将发现安装、启用模组、编辑设置和构建服务器包串联起来。第一阶段使用本机已有安装，第二阶段引入 SteamCMD 和创意工坊浏览。优先支持当前 Windows 64 位服务器启动脚本；Linux 导出和独立桌面安装器留作后续交付。

## 第一阶段：本地配置与构建（已实现）

### 文件发现

注册表 SteamPath/InstallPath → 默认位置 → libraryfolders.vdf → appmanifest。读取安装分支和 buildid。扫描 Steam 库及游戏嵌套工坊、本地 mods、现有服务器 INI/Lua。支持手动补充路径。缺失路径不使整个扫描崩溃，符号链接不递归；打包仅使用 AppID 380870 的 Dedicated Server；安装必须包含有效启动脚本、JRE 和服务器主类才可构建，支持 `java/projectzomboid.jar` 布局。客户端安装只用于发现工坊及未安装专用服务器时的沙盒预览。

### 配置模型

内部 Mod ID 与 Workshop ID 分开维护。按 mod.info 读取依赖，保留多版本选项；构建拦截缺失依赖、顺序错误和重复 ID。地图名称从 media/maps 读取，用户决定顺序和出生配置。保留未知 INI 键与注释。沙盒支持可识别数值、布尔、字符串字段和完整文本，不执行 Lua。

### 构建流水线

校验配置 → 临时目录复制运行环境 → 复制模组包及 B42 common 资源 → 写入独立缓存目录和配置 → 生成传参启动脚本 → 生成来源清单 → 原子重命名发布 → 自动隔离启动冒烟测试。复制出错清理未完成目录，源文件保持不变。提供后台阶段、文件计数、实时日志及测试报告。

### 2026-10-04 补充功能

- 工作台手动刷新重新读取本机安装及模组元数据，保留启用顺序、来源选择、目标版本、搜索与服务器设置；已删除的来源提示失效并阻止构建。
- 模组卡片显示分类及来源、作者、模组版本、作者声明的游戏版本范围、版本目录、说明、依赖、声明冲突和本机修改时间。缺失信息明确标记。分类优先读取 category/tags，否则依据地图和内容目录推断，不能等同工坊官方分类。
- 可手填目标游戏版本，或使用运行环境识别出的版本；Steam buildid 与游戏版本号分开。版本范围、目录、依赖与 incompatible 提供静态风险提示，不能据此保证脚本兼容。
- 构建成功后自动测试：复制配置及所选模组到临时缓存，不带现有存档；随机管理员凭据、无 Steam、本机临时 UDP 端口，等待 SERVER STARTED，默认最多 180 秒。支持停止测试；结束清理测试缓存，包保持可用。
- 界面显示实时启动日志、就绪状态、耗时、警告/错误数量与模组错误证据。完整日志及 JSON 报告保存到包的 diagnostics 目录。超时、Java/端口异常与模组问题分别显示；不能定位时明确写出无法归因。测试只证明启动，不覆盖多人连接、全部 Lua 交互及 Steam 服务。

### 验收

- 本机默认 Steam 库可自动识别，补充路径可扫描迁移后的安装。
- 可导入现有配置，搜索、启停、排序模组，编辑 INI 和沙盒。
- 构建输出含运行时、模组、配置、清单和启动脚本，独立缓存不覆盖现有服务器数据。
- 自动化测试验证配置、包结构、隔离启动流程、取消/超时、日志脱敏和归因。真实游戏启动另行记录；多人入服仍需手工验证。

## 第二阶段：SteamCMD 与创意工坊（未实现）

按以下四次迭代交付，工坊 API 权限与 Steam 登录方式首先做验证，不承诺所有接口匿名可用。

1. **SteamCMD 与统一任务队列**：发现/安装 SteamCMD，账号交互登录和 Steam Guard，不保存密码。实现按 Workshop ID 下载、校验、取消、重试和实时进度；以工坊条目为下载单位，多个内部 Mod ID 合并为一个任务。完成一个真实条目的登录→下载→扫描验收。
2. **工作台详情与更新检查**：每张卡片一键打开创意工坊（本次已加入链接）；接入官方条目详情，展示远端更新时间、描述、标签及可获取的版本说明。对照本机 Steam 工坊 manifest 和下载记录显示“最新 / 可更新 / 无法确定”。mod.info 模组版本和本机文件修改时间不能单独证明最新；本地模组显示不支持工坊更新。增加“检查该模组更新”和“检查全部更新”，显示检查时间与接口失败状态。
3. **一键更新单项与全部模组**：卡片更新按钮只在可更新时可用；工作台“更新全部”先展示将更新的工坊条目（范围为扫描到的工坊模组，按 Workshop ID 去重）。下载先进入暂存区，成功解析、校验后备份并替换受管缓存，失败恢复；未受管的 Steam 原目录与本地副本不自动覆写。下载状态同时出现在卡片和队列，单项失败不丢失其余任务结果。与构建互斥，防止复制中途更新。完成后刷新信息，保留启用列表与顺序；ID 删除、依赖变化明确提示重新选择。模组更新不自动覆盖已导出的包，需重新构建和测试。
4. **应用内浏览与完整联动**：搜索、分页、详情、合集展开，显示已有/待下载/下载中/可更新状态；一键下载后直接进入工作台。验收浏览→下载→选择→检查更新→单项更新→全部更新→刷新保留配置→构建冒烟测试，覆盖网络失败、登录失效、取消、重复条目、回滚与版本冲突。多人入服作为独立真机验收。

界面交互目标：工作台顶部提供“刷新本机”“检查全部更新”“更新全部”，卡片提供“工坊详情”“检查更新”“更新此条目”。更新按钮同时影响同一工坊条目下的所有内部模组，明确展示这一范围。第二阶段的在线检查和更新操作本次仅更新计划，尚未接入 SteamCMD。

## 后续质量提升

第三阶段可引入 Electron 桌面安装器、目录选择器、ZIP 导出、增量构建、版本兼容数据库、可视化出生地图、存档备份与服务器进程管理。当前设计将文件核心与 HTTP 界面分离，后续可替换外壳。

## 已知限制

仅靠 mod.info 不能可靠识别所有冲突、可选依赖或客户端专属模组。复杂 Lua 仅文本保留。复制体积和耗时随安装及模组增长；构建前检查空间，复制错误回滚。第一阶段不下载缺失文件。冒烟测试不自动二分排查或禁用模组，日志只能给出证据支持的候选，不能保证所有冲突都能唯一定位。实际包首次启动的管理员密码仍由用户输入，测试管理员仅存在于临时缓存。

## 2026-10-04 第二次第一阶段修缮

工作台收紧为图标与标题/兼容提示、元数据、来源选择、折叠说明的布局；去除重复路径与版本标签。统一默认、项目迁移、服务器构建与验证脚本到 Dedicated Server，修正 Steam 自带脚本的 %1/%2 参数限制，保留原版参数及独立缓存。新增原版和已启用模组的全部沙盒选项分组面板，搜索、展开/收起、带类型与约束的编辑，以及保留全文的安全 Lua 数据解析。历史导出包需重新构建，运行环境不会被迁移脚本直接覆盖。

## 2026-10-05 第一阶段归档补充

已交付模组列表名称/修改日期/工坊编号排序、加载顺序拖拽、递归自动启用前置；服务器分类取自游戏 SettingsTable，覆盖 INI、原版及模组沙盒。每配置 JSON 快照保存模组来源、顺序、设置、运行环境、筛选和未应用草稿；原路径失效时保留模组身份并提示。配置列表支持悬停操作、加载、自动命名复制、行内重命名及确认删除，历史备份与回收区独立存放。第一阶段源码以 v0.1.0 归档；在线 SteamCMD/创意工坊功能继续按第二阶段迭代。
