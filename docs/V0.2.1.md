# v0.2.1 更新与使用提示

文档更新：2026-11-10。版本源码标签：`v0.2.1`。

## 本次更新

- 开服控制台新增“＋ 新建服务器包”，支持默认配置或复制已有配置。
- 服务器包扫描、选择、编辑集中到开服控制台，补充路径可记住。
- 顶部显示当前编辑对象、保存位置、未保存修改和未应用草稿；切换配置可取消或放弃修改。
- 100 个已分类的内置服务器配置键有中文名称，可用中文搜索；模组未提供的中文说明不作自动承诺。
- 模组卡片精简信息，更新弹窗支持勾选与关闭；修复本机多副本导致重复更新提示的问题。
- 下载面板展示队列处理进度、当前条目、阶段、耗时，以及 SteamCMD 实际提供的百分比。
- 打包脚本检测标准输出目录中的运行实例，避免覆盖打包损坏正在使用的应用。

## 启动与升级

1. 先在旧工作台保存修改，停止游戏服务器，并结束下载和构建任务，再正常退出应用。单实例机制会把新启动请求交给仍在运行的旧实例；仅收起窗口不等于退出。
2. 打开新版，确认右上角显示 **v0.2.1**。
3. 在开服控制台扫描旧服务器包；无需移动旧存档。新建包不会自动迁移旧世界。

源码用户执行 `npm ci` 后用 `npm start` 开发运行；`npm run pack:win` 输出 `release/win-unpacked/PZ Server Studio.exe`，`npm run dist:win` 生成便携应用。解包版必须保留整个目录，不能只复制 EXE。

当前本地交付的 `launch-latest.cmd` 指向 `release/build-v0.2.1/win-unpacked/PZ Server Studio.exe`。该目录属于本机构建产物，不随 Git 上传；新克隆仓库请使用上述命令，不要把此脚本当作下载或自动升级器。

开发模式使用源码目录的 `data`、`output`；打包后的应用使用 `%APPDATA%/PZ Server Studio/workspace`。本机游戏配置仍从用户的 `Zomboid/Server` 目录读取。程序资源、工作台缓存和游戏服务器包是不同目录。

## 配置与服务器包

“本机配置”是制作服务器包的设置与模组清单；“服务器包”包含已经复制的运行环境、模组和配置。保存本机配置不会自动改写已有服务器包。

在“项目与资源”加载或新建配置，在模组页和服务器配置页编辑，然后保存。原文编辑器的草稿需要点击“应用编辑内容”才参与游戏配置；保存工作台进度可以保留草稿，但不等于应用草稿。

要调整已有包，先在开服控制台停止该服务器，再点击“编辑此服务器包”。确认顶栏编辑对象和保存位置，保存后在下次启动生效。新增或更新模组文件需要重新构建，不能只保存旧包配置。

## 新建服务器包

1. 在开服控制台的服务器包选择栏旁点击“＋ 新建服务器包”。
2. 填写包名称（1–64 位字母、数字、下划线或连字符）；游戏内显示名称可使用中文。
3. 选择默认配置或已有配置，设置内存和已安装的 Project Zomboid Dedicated Server。复制已有配置时，可取消“保留所选配置的启用模组”。
4. 点击“创建并测试”。应用联网下载并核验工坊模组、复制运行文件并执行隔离启动测试；在“构建与测试”查看日志。
5. 完成后控制台刷新并选中新包。确认测试结果，再执行启动前检查和一键启动。

此操作保留当前工作台修改与原配置，不复制旧存档，也不自动启动常驻游戏服务器。测试失败时可能保留已生成的包；“包已生成”不等于“可正常游玩”。

## 模组更新状态

- **有更新**：需要下载较新的工坊内容，可以在更新弹窗选择条目。
- **本机已有新版 · 当前来源较旧**：本机已存在新版，无需重复下载；在“信息与来源”选择对应新版。若当前正在编辑已有服务器包，应重新构建包。
- **版本未知或查询失败**：尚不能确认版本，不能视为最新。检查网络、条目访问权限及登录状态，再重试。

进入模组页自动检查更新，五分钟内复用结果；下载与重新扫描时暂停自动检查，完成后再刷新结果。右上角 × 和“稍后处理”只关闭弹窗，不会创建下载任务。

更新下载到应用自己的工坊缓存，不改写 Steam 的原始安装文件，也不替换已有服务器包里的模组。按工坊条目更新，同一条目包含的多个内部 Mod ID 会一起下载。构建服务器包仍执行独立的最新版校验；“无需重复下载提示”不表示构建阶段跳过校验。

## 下载进度怎么看

队列条显示已处理条目数，同时列出成功、失败和取消数量；已处理包含失败与取消，因此队列到达终点不表示全部成功。

当前条目显示连接 Steam、等待登录验证、下载、校验或导入阶段，以及耗时。SteamCMD 提供下载百分比时才显示数值；未提供时显示活动进度，不承诺下载速度或剩余时间。字节数只在 SteamCMD 提供时显示，不是持续测量的网络流量。

点击“查看任务与登录验证”可展开任务列表和日志。需要密码或 Steam Guard 时在对应输入框提交。失败条目可重试；点击弹窗关闭不会取消已开始的下载，需使用任务区的“取消下载”。

下载版本低于请求时的工坊版本会拒绝发布。文件导入后若版本记录保存失败，任务会明确报错，不伪装成功。

## 常见问题

**更新后界面仍和以前一样**：确认已退出旧实例，并检查实际启动路径和右上角版本号。多个 `release` 子目录中的 EXE 可能是不同构建。

**仍反复提示相同模组**：先确认使用 v0.2.1，再区分“有更新”和“当前来源较旧”。若确为更新失败，记录工坊编号、版本号和任务错误，在日志中检查原因。

**打不开或缺少运行文件**：解包版需要完整目录。不要在应用运行时覆盖其目录；退出后重新打包，或使用独立新目录构建。

**找不到服务器包**：在开服控制台选择包根目录（包含 `manifest.json`）或其直接父目录并扫描。更深的多层目录不会递归搜索所有内容。

**没有独立黑色终端窗口**：游戏服务器在后台运行，使用开服控制台的运行终端输入命令；“保存并停止”正常退出，强制终止可能丢失未保存进度。
